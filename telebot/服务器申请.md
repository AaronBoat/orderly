# 服务器资源申请 — Telegram 公告翻译机器人

**申请人：** Aaron  
**申请日期：** 2026年3月6日  
**所属项目：** Orderly 中文社区运营自动化  

---

## 一、项目背景

Orderly 英文 Discussion Forum 产生英文公告与社区消息，中文社区用户无法及时获取。为提升中文社区的信息同步效率，我们开发了一个基于 Python 的 Telegram Bot，能够实时监听英文 Forum 中指定的 Topic，通过 Google Gemini API 将消息翻译为中文，并自动转发至 Orderly 中文官方社区群组。

目前该机器人已完成开发与本地测试，**需要一台长期在线的服务器进行生产部署**。

---

## 二、服务需求描述

### 2.1 服务类型

需要一台 **Linux 云服务器（VPS）**，用于 24/7 不间断运行 Python 应用进程。

### 2.2 最低配置要求

| 配置项 | 最低要求 | 推荐配置 |
|--------|----------|----------|
| CPU | 1 核 | 1 核 |
| 内存（RAM） | 512 MB | 1 GB |
| 硬盘 | 10 GB | 20 GB |
| 操作系统 | Ubuntu 22.04 LTS | Ubuntu 22.04 LTS |
| 网络 | 可访问 Telegram API 及 Google API | 国际带宽 |
| 带宽 | 1 Mbps | 5 Mbps |

> ⚠️ **关键要求**：服务器网络必须能够直接访问以下境外服务，否则机器人无法正常运行：
> - `api.telegram.org`（Telegram Bot API）
> - `generativelanguage.googleapis.com`（Google Gemini API）

### 2.3 运行时依赖

- Python 3.10+
- pip 包：`python-telegram-bot==21.0`、`google-generativeai>=0.3.0`、`PyYAML>=6.0`
- 进程管理：`screen` 或 `systemd`（用于后台持久运行）

## 三、资源占用预估

| 指标 | 估算值 | 说明 |
|------|--------|------|
| CPU 占用 | < 5% | Bot 为事件驱动，绝大多数时间处于 idle 状态 |
| 内存占用 | ~80–150 MB | Python 运行时 + 库加载 |
| 日均流量 | < 50 MB | Telegram polling + Gemini API 调用 |
| 日均 API 调用 | ~50–200 次 | 取决于 Forum 消息量，峰值在工作日 |
| 日志写入 | < 5 MB/天 | 文本日志，每条消息约 200–500 字节 |

## 四、部署方案

```
服务器
└── /home/ubuntu/telebot/
    ├── main.py          # 主程序
    ├── config.yaml      # 配置文件（含 Bot Token、API Key，不上传 Git）
    ├── requirements.txt # 依赖列表
    ├── bot.log          # 运行日志
    └── start_bot.sh     # 启动脚本
```

启动方式：使用 `screen` 会话保持后台运行，并可配置 `crontab` 实现开机自启。

---

## 五、安全说明

- Bot Token 与 Gemini API Key 均存储于服务器本地 `config.yaml`，不会提交至代码仓库（已加入 `.gitignore`）
- 机器人仅具备**只读监听**目标群组的权限，以及向目标中文群**发送消息**的权限
- 无需开放任何对外端口，机器人使用 Telegram Long Polling 方式主动拉取消息

## 六、申请理由

当前机器人运行在开发者本机，存在以下问题：

1. **可用性差**：本机关机或休眠即导致机器人停止，消息无法及时同步
2. **网络不稳定**：本地网络波动会导致 Telegram API 连接中断
3. **无法无人值守**：需要人工保持开机状态，不适合长期运营

**申请云服务器后，可实现真正意义上的 7×24 小时自动化运营，无需人工介入。**
